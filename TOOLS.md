# Инструменты проверки и отладки

## Повседневное

```
npm run check        типы + линтер + тесты Rust + clippy без послаблений
npm run dev:debug    приложение с открытым портом отладки WebView2
npm run app -- ...   расспросить запущенное приложение
npm run db           заглянуть в базу без запуска приложения
```

`npm run check` — то, что прогоняется перед коммитом. Проходит целиком; если
падает, значит что-то сломано на самом деле.

## Отладка приложения

Tauri не Electron, обычные драйверы браузера к нему не подключаются. Но WebView2
отдаёт отладочный порт, и через него работает тот же протокол, что у Chrome.

```
npm run dev:debug                      запустить с портом 9222
npm run app -- text                    весь видимый текст страницы
npm run app -- route journal           перейти на экран
npm run app -- eval "return 2+2"       выполнить выражение
npm run app -- shot окно.png           снимок экрана
npm run app -- errors 10               следить за консолью
npm run app -- tabs                    список вкладок
npm run app -- click 2                 переключить вкладку
```

Две особенности, на которых легко ошибиться:

- **Выражение для `eval` должно быть в одну строку.** Перенос теряется при
  передаче аргумента через npm, и команда молча вернёт пустоту.
- **Клик по вкладкам делается настоящими событиями мыши.** Radix слушает
  события указателя и на `.click()` из скрипта не реагирует — из-за этого можно
  решить, что вкладки сломаны, хотя они работают.

## База данных

```
npm run db              сводка: остатки по позициям и местам, операции
npm run db -- check     сверка остатков с журналом, целостность
npm run db -- tables    таблицы и число строк
npm run db -- sql "..." произвольный запрос
```

Работает всегда с копией вместе с файлом WAL: приложение может держать базу
открытой, а часть данных — лежать в журнале. Отдельный клиент SQLite не нужен,
используется встроенный в Node модуль.

## Периодическое

Не входит в `check`, потому что требует сети или заметного времени.

```
npx knip                              мёртвые файлы, экспорты, зависимости
cargo machete                         неиспользуемые зависимости Rust
cargo audit                           уязвимости в зависимостях
cargo fmt                             форматирование Rust
npm run lint:fix                      автоисправления линтера
```

**`knip`** стоит гонять после любой крупной правки: за одну проверку он нашёл
30 неиспользуемых компонентов, 22 лишние зависимости и библиотеку графиков, для
которой в сборке был заведён отдельный пустой кусок.

**`cargo audit`** сообщает и о тех уязвимостях, которые в сборку под Windows не
попадают — они приходят по путям для macOS и Linux. Проверить, входит ли пакет
в сборку:

```
cargo tree --target x86_64-pc-windows-msvc -i имя-пакета
```

Пустой вывод означает, что под этой платформой пакет не компилируется и
предупреждение к приложению не относится.

## Планы запросов

Проверить, что индексы используются:

```
npm run db -- sql "EXPLAIN QUERY PLAN SELECT ..."
```

`SEARCH ... USING INDEX` — индекс работает. `SCAN` по большой таблице означает
полный перебор; для маленьких справочников это нормально.

## Чего намеренно нет

- **Тесты фронтенда.** Логика ушла в Rust, во фронтенде остались разметка и
  вызовы команд — покрывать там почти нечего.
- **`no-explicit-any` как ошибка.** Остаются места с `any`, каждое требует
  осмысленного типа. Правило понижено до предупреждения, чтобы `check` ловил
  новые ошибки других видов и не был красным постоянно.
